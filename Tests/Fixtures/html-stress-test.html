marc HTML stress test

This page exercises every part of marc's HTML reader that can be exercised from a well-formed document: the outline, block identity, the reading bridge, the link graph, the external-resource prompt, and the scroll tracker. Nothing here is malformed. Everything here should work.

The companion file html-stress-torture.html holds the malformed cases, which are expected to break. Keep the two apart so a failure in one does not hide a failure in the other.

The last section of this page reports whether the DOM walker in HTMLPreview.swift found the same blocks, in the same order, as the source parser in HTMLStructure.swift. That is the invariant the whole feature rests on: ordinal 7 in the source must be element 7 on screen.

7. Layout and the scroll tracker

The reading bridge reports each block's rectangle. These are the rectangles that are awkward: taller than the viewport, stuck to the top, zero-height, hidden outright, and inside a scrolling container.

7.1 A block taller than the viewport

The block below is 2400 pixels tall. It should not be marked read the moment its top edge appears, and it should not stay unread after it has been scrolled all the way through.

7.2 A sticky heading

A sticky element keeps reporting a rectangle at the top of the viewport for as long as it is stuck. If the tracker uses a reading line near the top, this is the block most likely to be marked read wrongly, or to hold the reading line against blocks that scroll past underneath it.
